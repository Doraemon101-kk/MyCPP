## 1 类型和对象先分清

```cpp
using Report = std::vector<std::pair<std::string, int>>;
Report report{{"cat", 2}, {"dog", 5}};
```

`Report`是类型别名，`report`是这个类型的对象。`pair`把两个值组合起来，`.first`访问词，`.second`访问次数。`vector`保存多个pair。

```cpp
for (const auto& entry : report) {
    std::cout << entry.first << ' ' << entry.second << '\n';
}
```

这段代码中，`auto`推导元素类型；`&`借用原元素；`const`限制通过entry修改原元素。范围for只有一个冒号，结构是“元素声明 : 遍历对象”。

### 与C的对应

| C中的经验 | C++中的联系 |
|---|---|
| struct把若干字段组合 | pair、struct、class都能组织复合数据 |
| 通过指针读写调用方对象 | 引用参数也可以访问调用方对象 |
| 数组首地址与长度 | vector把数据与元素数量、容量一起管理 |
| 回调函数参数 | 普通函数、lambda、函数对象都可作为规则传入 |

## 2 值 引用 const引用

```cpp
int value = 10;
int copy = value;
int& alias = value;
const int& reader = value;
alias = 20;
```

此时value为20，copy仍为10，通过reader读取到20。copy是独立对象；alias和reader都访问value。const约束的是通过reader这条访问路径的修改权。

```cpp
void inspect(const Report& source); // 只读借用
void update(Report& source);        // 可以修改调用方对象
void consume(Report source);        // 得到自己的参数对象
```

按值接收普通左值时，参数通常由复制得到；传入可移动对象时也可能移动。返回值优化和移动会影响具体构造次数。

你用过的`auto result = select_where(...)`中，result由返回值初始化；`auto`负责类型推导，不是“自动变成指针”。

## 3 生命周期和RAII

自动存储期的局部对象通常在执行到其声明时构造，在离开作用域时析构。正常结束、return和异常退出作用域都会对已构造的局部对象执行相应析构。

```cpp
{
    std::string text = "hello";
    // text在这里有效
}
// text的生命周期已经结束
```

引用提供访问途径，资源由其所有者管理。C中常见的配对是malloc/free、fopen/fclose；C++通过对象的构造和析构组织配对操作，这就是RAII。

```cpp
bool readable(const std::string& path)
{
    std::ifstream file(path); // 需要 <fstream>
    return file.is_open();    // 函数退出时file自动关闭所管理的文件
}
```

### 返回对象和返回引用

```cpp
std::string make_text()
{
    std::string result = "hello";
    return result;
}
```

调用方获得结果对象；实现可以使用复制消除或移动来高效传递。

错误示例：

```cpp
const std::string& bad_text()
{
    std::string local = "hello";
    return local; // local销毁后，返回的引用悬空
}
```

这与C中返回局部变量地址是同一种生命周期问题。返回参数引用或容器元素引用时，也要检查调用方使用期间原对象是否仍然存在、位置是否仍有效。

直接绑定某些临时对象的局部const引用可以延长临时对象寿命，例如`const std::string& s = std::string("hi");`。这种规则有具体绑定条件，函数返回一个已悬空的引用时，再用const引用接收也无法恢复原对象。

## 4 string与string_view

`std::string`管理字符存储。`std::string_view`记录字符序列的位置与长度，用于借用已有字符。

```cpp
std::string text = "hello";
std::string_view view = text;
text[0] = 'H';
// view现在读到Hello；text仍活着，修改单个字符没有重新分配
```

视图适合函数执行期间只读观察字符串，能避免创建一份字符串副本。使用期间要保证字符来源有效。

错误示例：

```cpp
std::string_view bad_view()
{
    std::string local = "hello";
    return local;
}
```

这里按值返回了视图，但没有返回它借用的字符。可以联系C中的`struct { const char* data; size_t length; }`：复制结构体时复制的是地址和长度。

返回指向字符串字面量的视图，例如`return "hello";`，其字符具有静态存储期，寿命足够长。返回指向调用方字符串的视图，则由调用方负责维持来源有效。

## 5 begin end和迭代器

```cpp
auto it = words.begin();
while (it != words.end()) {
    std::cout << *it << '\n';
    ++it;
}
```

`begin()`指向首元素，`end()`位于末元素之后；空容器二者相等。迭代器到达end时停止，访问元素前应确保位置有效。

对于vector<string>，`*it`是string，`it->size()`调用字符串长度函数。对于map<string,int>，`*it`是键值对，`it->second`访问次数。

`it->second`可以理解为`(*it).second`。`it.second`则试图访问迭代器对象自己的second成员。

不同容器提供自己的迭代器类型。C++允许自定义类型重载`operator++`：vector迭代器向下一个元素移动，map迭代器向键顺序的下一个元素移动。调用方使用统一的遍历形式。

## 6 vector的大小 容量和失效

| 接口 | 含义 |
|---|---|
| size() | 已有元素数 |
| capacity() | 当前空间能容纳的元素数 |
| reserve(n) | 容量不足时申请至少n个元素的空间 |
| resize(n) | 改变实际元素数，必要时构造或销毁元素 |
| data() | 当前连续元素存储的起始地址 |

`reserve`之后size保持原值。对空vector调用reserve后，它仍然没有可供普通迭代器写入的第一个元素。

### 下一次要做的观察实验

```cpp
std::vector<int> values{10, 20};
auto old_capacity = values.capacity();
std::cout << values.size() << ' ' << values.capacity()
          << ' ' << static_cast<const void*>(values.data()) << '\n';

values.reserve(old_capacity + 1); // 确保触发重新分配

std::cout << values.size() << ' ' << values.capacity()
          << ' ' << static_cast<const void*>(values.data()) << '\n';
```

关注三件事：size保持2；capacity增大；存储地址可能从输出中观察到变化。判断引用失效以操作规则为依据。

| 操作 | 失效规则 |
|---|---|
| vector发生重新分配 | 原元素迭代器、引用、指针全部失效 |
| vector尾部追加且没有重新分配 | 原元素的引用和迭代器仍有效，原end失效 |
| vector.erase | 删除位置及之后的迭代器和引用失效，包含原end |
| map.erase某个元素 | 被删除元素的迭代器和引用失效，其他元素仍有效 |

安全访问可以保存仍然适用的下标，操作后通过容器重新取得元素。下标指向的逻辑元素也要核对：删除前方元素后，同一个下标可能对应别的元素。

## 7 安全删除与erase-remove

### 迭代器删除

```cpp
for (auto it = counts.begin(); it != counts.end();) {
    if (it->second < minimum) {
        it = counts.erase(it);
    } else {
        ++it;
    }
}
```

循环始终保持“it指向下一个待检查元素”。删除分支接收erase返回的位置；保留分支向前一步。循环头不统一递增，避免删除后跳项。

vector也可用同样结构，不过单次删除可能向前搬动许多后续元素。大量逐项删除的总成本最坏可达O(n²)。

### erase-remove_if惯用法

```cpp
auto logical_end = std::remove_if(
    words.begin(), words.end(),
    [minimum](const std::string& word) {
        return word.size() < minimum;
    });
words.erase(logical_end, words.end());
```

remove_if把保留元素集中到前方，保持保留元素相对顺序，返回逻辑末尾。此时容器size仍是原值，逻辑末尾之后的内容不作为筛选结果。随后erase删除尾部，让size真正缩短。这个组合整体为线性复杂度。

```text
输入：[a, b, cat, dog]
筛选后有效部分：[cat, dog | 尾部不再作为结果]
erase后：[cat, dog]
```

区间`[first,last)`包含first指向的位置，排除last；当first==last时是空区间。

## 8 函数模板和类型推导

```cpp
template<class T, class Predicate>
std::vector<T> select_where(
    const std::vector<T>& input,
    Predicate predicate);
```

T描述元素类型，Predicate描述可调用规则的类型。两个名字都是自己起的类型参数名。实际调用时由实参推导：传vector<int>时T为int，传词频报告时T为pair<string,int>。

```cpp
template<class T, class Predicate>
std::vector<T> select_where(const std::vector<T>& input, Predicate predicate)
{
    std::vector<T> result;
    for (const T& element : input) {
        if (predicate(element)) result.push_back(element);
    }
    return result;
}
```

逐行读：创建拥有元素的结果容器；以const引用遍历输入；把元素交给规则；将选中元素复制到结果；返回结果。输入不变，结果拥有独立元素。

模板要求传入类型支持函数体使用的操作。这里需要谓词能处理元素，且选中元素能复制进结果。编译器根据具体类型实例化函数，错误通常在实例化时暴露。

## 9 lambda和谓词

```cpp
int minimum = 3;
auto rule = [minimum](const auto& entry) {
    return entry.second >= minimum;
};
```

方括号是捕获列表；圆括号是调用参数；大括号是函数体。entry由每次调用提供，minimum在创建lambda时按值保存。

```cpp
int limit = 3;
auto saved = [limit](int n) { return n >= limit; };
auto borrowed = [&limit](int n) { return n >= limit; };
limit = 10;
// saved(5)为true；borrowed(5)为false，此时limit仍然活着
```

按值捕获适合保存阈值快照。按引用捕获访问外部变量的当前状态，调用期间该变量需要仍然有效。

错误示例：

```cpp
auto bad_rule(int minimum)
{
    return [&minimum](int n) { return n >= minimum; };
}
```

返回后参数minimum销毁，lambda保存的引用悬空。按值捕获`[minimum]`可让规则独立保存阈值。

谓词返回值的含义由算法约定：remove_if中true表示删除，copy_if和本次select_where中true表示选入结果。

## 10 copy_if和输出迭代器

```cpp
std::vector<T> result;
std::copy_if(input.begin(), input.end(),
             std::back_inserter(result), predicate);
return result;
```

copy_if负责遍历与判断；predicate给规则；back_inserter把输出操作转换成对result的push_back；vector负责保存元素。

空result的begin等于end，普通输出迭代器需要有效的可写位置。back_inserter会追加元素，适合从空容器开始收集。

复杂度通常是遍历n个输入并调用n次谓词；若选中k项，结果保存k个元素。这里的复制和predicate自身也可能有额外成本。

## 11 值返回和std::move

```cpp
Report make_report()
{
    Report result{{"cat", 2}};
    return result;
}
```

普通报告优先按值返回：对象组织简单，返回时可利用复制消除或移动。返回局部值通常直接写return result，让语言规则和编译器选择构造方式。

std::move把表达式转换为可参与移动的形式。实际资源转移由后续构造或赋值操作完成。对于普通非const vector，移动构造通常接管它的动态存储；之后原vector仍是有效对象，具体内容按对应操作保证判断。

const对象通过std::move传递时仍带const属性，常见移动构造无法接收它，因此可能选择复制。选择参数的值/引用方式，会影响后面能否移动。

## 12 unique_ptr与shared_ptr

```cpp
auto owner = std::make_unique<int>(42);
int* borrowed = owner.get();
auto next = std::move(owner);
// owner为空，next拥有原int；borrowed仍指向那个int
next.reset();
// next为空，int已销毁；borrowed悬空
```

unique_ptr独占管理资源，禁止复制，支持移动。get借出普通指针，reset释放当前拥有的对象并可接管新的对象。普通借用指针由所有者的资源寿命约束。

你的报告保存函数：

```cpp
std::unique_ptr<Report> keep_report(Report report)
{
    return std::make_unique<Report>(std::move(report));
}
```

参数report是函数持有的对象。make_unique在动态存储上创建新Report，以参数移动构造它，并返回其独占所有者。函数结束后，调用方得到的所有者继续管理新报告。

### 何时选哪一种

| 方式 | 使用场景 | 访问方式 |
|---|---|---|
| Report值对象 | 普通结果与数据传递 | report.size() |
| const Report& | 函数执行期间只读借用现有对象 | report.size() |
| unique_ptr<Report> | 明确的动态对象独占所有权，需要可转移或空状态 | owner->size() |
| shared_ptr<Report> | 多个独立所有者共同决定动态对象寿命 | owner->size() |

```cpp
auto a = std::make_shared<std::string>("hello");
auto b = a;   // 共同拥有同一个对象
a.reset();
// b仍拥有对象
```

共享所有权使对象活到最后一个所有者释放；需要额外的管理成本。对象之间相互持有shared_ptr可能形成循环，适当方向可以改为weak_ptr观察。当前报告示例通常用值返回就足够，unique_ptr版用于练习独占所有权。

### 空报告与空指针

空vector是一个存在但没有元素的对象，使用`.empty()`判断。空unique_ptr表示没有拥有对象，使用`if(owner)`判断是否存在；访问`*owner`或`owner->...`前先确认非空。

```cpp
auto selected = select_where(source, rule);
if (selected.empty()) return nullptr;
return std::make_unique<Report>(std::move(selected));
```

这正是你最后完成的组合逻辑。阈值相等保留；结果与输入独立；没有符合项时用nullptr表达没有报告。

## 15 模板定义与编译链接

头文件负责让使用者看到声明。普通函数可以在一个cpp中定义，编译后由链接器组合。函数模板通常在调用处需要完整定义来实例化具体版本，因此常把定义放在头文件。

```cpp
// select.hpp
#pragma once
#include <vector>
template<class T, class Predicate>
std::vector<T> select_where(const std::vector<T>& input, Predicate predicate)
{
    std::vector<T> result;
    for (const T& element : input)
        if (predicate(element)) result.push_back(element);
    return result;
}
```

调用文件包含此头文件。若只让它看到模板声明、把定义藏在另一个cpp中，常会遇到具体版本缺失或编译诊断；显式实例化能处理某些固定类型场景。本次模板跨文件故障实验是可选扩展，放在核心收尾之后。

## 16 你实际遇到的语法错误

| 原写法或困惑 | 改法与理由 |
|---|---|
| for(T:element:input) | for(const T& element : input)，声明与变量名之间用空格 |
| element.predicate() | predicate(element)，规则是独立传入的可调用对象 |
| it.second | it->second，先通过迭代器访问元素 |
| if(result)，result是vector | 用empty判断元素数量是否为零 |
| if(result.empty())时创建非空报告 | 空分支返回nullptr，非空分支创建报告 |
| 筛选后直接返回原report | 接住筛选结果，再返回它的值或所有者 |
| 用> minimum | 需求是达到阈值，使用>= |
| (void)parameter | 丢弃表达式值，用于占位时压制未使用警告，实际使用参数后可移除 |
| TODO异常还留着 | 实现完成后去掉占位throw，再运行测试 |
